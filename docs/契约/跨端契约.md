## 1 JSON 备份格式（**两端唯一数据桥梁**）

来源：桌面 **v0.22.3（R33）** 起已具备的全保真备份通道 `GET /api/v1/export` / `POST /api/v1/import`。

```jsonc
{
  "cycles": [                       // 周期记录（按 period_start 升序）
    {
      "period_start": "2027-02-10", // YYYY-MM-DD，必填
      "period_end":   "2027-02-17", // YYYY-MM-DD，可空
      "cycle_length": 33,           // 天；首条为 null（没有上一条可比）
      "period_days":  8,            // 天
      "note": "",                   // 文本，可空
      "is_anomalous": false
    }
  ],
  "predictions": [                  // 历史预测（含精度评估依据）
    {
      "predicted_date":       "2027-02-08",
      "predicted_start_lower":"2027-02-05",
      "predicted_start_upper":"2027-02-11",
      "confidence":           0.8571,
      "model_version":        "bayesian_v1",
      "actual_date":          "2027-02-10",  // 已验证才有；未验证为 null
      "error_days":           2,             // |actual - predicted|；未验证为 null
      "created_at":           "2026-03-15 12:00:00"
    }
  ],
  "model_params": {                 // 可空；导入端**允许重算**（桌面即重算）
    "mean_cycle": 31.668996622012557, "std_cycle": 2.0, "n_records": 4,
    "ema_cycle": 30.875499999999995, "prior_mean": 31.668996622012557,
    "prior_std": 1.005675672006492, "prior_weight": 0.5555555555555556
  },
  "app_settings": { /* 键值对，按桌面实现为准 */ },
  "exported_at": "2026-10-04",
  "predictions_total": 5,
  "predictions_truncated": false
}
```

**硬性约束（两端都必须满足）**：

1. **字段名逐字一致**（含 `predicted_start_lower` / `predicted_start_upper` 的上下界语义：
   `lower <= upper`，区间为闭区间）；
2. **日期格式** `YYYY-MM-DD`；时间戳 `YYYY-MM-DD HH:MM:SS`（本地时间，秒级，**可能并列** ⇒ 见 §2.3）；
3. **空数组 vs 缺字段**：`cycles` 必须是数组（可为 `[]`）；全空导入必须被拒（桌面口径 `400 EMPTY_IMPORT`）；
4. **导入语义 = 清空重建**：桌面 `POST /import` 会**清空该账号现有数据**再写入
   ⇒ 安卓端**必须**在 UI 上给出同等强度的确认（"会清空现有数据"）；
5. **`cycle_length` 与 `period_days` 是派生字段**：桌面导入时会**重算**
   ⇒ 安卓端也必须能独立算出同样结果（口径见 §2.1）；
6. **精度报告需要 `predictions` 的历史**：只导 `cycles` **不会**有精度数据
   （桌面 CSV/PDF 通道即如此）⇒ 安卓端 UI 必须如实告知。
7. **`created_at` 不参与往返保真**（**顾问 2026-10-10 裁定**）：
   两端导出时**都不携带** `cycles[].created_at` 的原值（桌面自己往返同样丢 ⇒ 这是**契约层**的选择、
   不是某一端的偏差）。**判据**：往返比对时不得因 `created_at` 报 FAIL；
   但**算法口径不变** —— `predictions[].created_at` 仍参与"排序键"（§2.3），
   且"任何时间序都不得依赖它"（§2.3 第 1 条）这条**照旧成立**。

## 2 算法口径（**golden vectors 是唯一凭证**）

### 2.0 比对口径：结构优先于字节（**顾问 2026-10-10 采纳 R4 实测**）

**凡是"文本里包 JSON"的字段，一律"解析后按结构逐值比"，不比字节**：

| 字段 | 为何不能比字节 |
|---|---|
| `predictions[].model_params_json` | 桌面用 Python `json.dumps`、安卓用 `org.json` ⇒ **键序与空格本就不保证一致**（R4 实测：解析后 9/9 键**值全等**，差异只在字节） |
| `model_params` 对象本身 | 同上（两端序列化器不同） |

**判据**：① 先 `json.loads` 两侧；② 按键集合比（键集合必须相同）；③ 值按 §2.2 的**显式容差**逐个比；
④ **只在解析失败或键集合不同时**才报 FAIL。**禁止**用"原始字符串相等"当判据（那是橡皮筋）。

### 2.1 派生字段
- `period_days = (period_end - period_start).days + 1`；
- `cycle_length = (本条 period_start - 上一条 period_start).days`；**首条为 null**。

### 2.2 统计（分析页口径，来自 `algo/stats.py`）
- **平均周期** = 有效 `cycle_length` 的**简单均值**（注意：**不是**模型后验均值，见 §2.4）；
- **平均经期** = `period_days` 的简单均值；最短/最长取有效 `cycle_length` 的极值。

### 2.3 预测与精度
- 冷启动阶段：`cold_start_1` / `cold_start_2`，随后 `bayesian_v1`；
- 精度指标：`hit_rate_pm1 / hit_rate_pm2 / mae / interval_coverage / bias / trend`；
- **`trend` 的排序锚 = `predicted_date`**（不是行 id，也不是列表顺序）——
  这是桌面 **v0.22.4（R33-fix1）/ v0.22.5（R34-A）** 用事故换来的口径，
  **安卓端必须一致**，否则同一份数据两端结论相反；
- **`created_at` 可能并列**（历史迁移/导入所致）⇒ **任何"时间序"都不得依赖 `created_at` 或行 id**。

### 2.4 两个"均值"不是一回事（**UI 文案必须区分**）
| 名称 | 出处 | 含义 |
|---|---|---|
| **平均周期**（分析页） | `algo/stats.py` | 有效周期的**简单均值** |
| **周期均值**（算法透视镜 / PDF 参数表） | 贝叶斯模型 | **后验/加权均值**（受先验与 EMA 影响） |

同一账号两者**本来就不相等**（实测例：`31.75` vs `31.669`）⇒ 两端文案**不得**混用成同一个词。

## 3 golden vectors（R2 交付）

- **由桌面 Python 实现导出**（`python3.11`，只读、临时库）；
- 覆盖三类：**随机**（≥8 种子，同时报告噪声）/ **边界**（0/1/2 条记录、首条无 cycle_length、
  并列 `created_at`、`error_days=0`、超长周期）/ **真实数据**（用户库脱敏后的周期与预测序列）；
- 格式：`[{ "name": …, "input": {…}, "expect": {…} }]`，落在 `docs/契约/golden/`（**不含任何真实身份信息**）；
- **Kotlin 侧必须逐值通过**；浮点容差**必须显式声明**（建议 `1e-9` 相对误差）并写进报告，
  **不得**为了让测试变绿而放宽。

## 4 前端资产：单一来源 + 运行时门控

- **来源**：仓库内 `frontend/`（**唯一**）；`vendor/frontend` 快照与 `frontend.sha256` 清单已于 R15 退役；
- **引入方式**：构建期 `tools/copy_frontend.py` 清空并逐文件复制到 `app/src/main/assets/www/`
  （该目录被 `.gitignore` 忽略）；源缺 `index.html`、发现数据文件或复制数量不符都会使构建失败，**无绕过开关**；
- **禁止分叉**：安卓差异**只能**通过运行时门控：

  | 门控 | 谁注入 | 作用 | 与**行为**有关的既有实现 |
  |---|---|---|---|
  | `piq-shell` | 桌面宿主 | 标题栏 / 滚动条等桌面专属 | 前端 `js/shell.js` 读 class |
  | **`piq-android`** | **安卓宿主** | 关 Service Worker、隐藏桌面专属、切换传输层 | ⚠ **前端源码里 0 命中** ⇒ 安卓侧必须**宿主注入**（见下） |

- **安卓侧门控实现（R2-a 实测确立的做法，供复用）**：
  1. **class 注入**：页面 document-start 注入 `document.documentElement.classList.add('piq-android')`
     （与 `piq-shell` 同风格，**不改前端源码**）；
  2. **关 Service Worker**：前端 `js/app.js` 会自行 `navigator.serviceWorker.register('/sw.js')`，
     宿主拦不住"浏览器自动注册"⇒ 用 **`Object.defineProperty(Navigator.prototype,'serviceWorker',…)`
     放一个必然抛错的替身**，让注册变成可预期的失败；**证据形态**：console 出现宿主替身文案、
     **无** `/sw.js` 取回尝试（`⚠ 不要用 shouldInterceptRequest 的计数当判据——SW 取回不经过它`，R2-a 实测）；
  3. 门控**只影响行为**，**不得**改文案与业务语义。
- **资产根映射（R2-a 实测确立，⚠ 两个坑）**：

  | 请求 | 必须落到 | 为什么 |
  |---|---|---|
  | `/theme/index.html`（入口） | 前端 `index.html` | 契约 §7.1：`/theme/*` 指向当前主题 |
  | `/js/*`、`/css/*`、`/index.html`、`/assets/*.webp` | **同一份前端树的对应路径** | 前端 `index.html` 用**绝对路径** `/js/app.js`，且 `js/app.js` 用 **`/assets/*.webp`** |

  ⚠ **坑 1**：若把 `/assets/` 映射到前端根，则 `/assets/celestial-planet.webp` 会被解析成
  `www/celestial-planet.webp` ⇒ **404**（R2-a Build A 实测）；必须让 `/assets/x` 落到 `www/assets/x`。
  ⚠ **坑 2**：映射表**必须覆盖 `/js/` 与 `/css/`**（或给一个**根兜底**处理器），否则 `/js/app.js` 落网络栈 ⇒ 白屏。
  ⇒ **正确写法 = 根兜底 + `/assets/` 透传前端根**（R2-a Build C/F 实测：三条路径全 200、页面正常渲染）。
- **`localStorage` 必须开**：真实前端用 `localStorage` 存会话（`js/api.js`）⇒ 安卓 WebView 的
  `domStorageEnabled` **必须为 `true`**（R1 骨架里是 `false`，R2-a 已改）。

## 5 传输层（R1 裁定后填实）

> **R5 后的实测订正（2026-10-11，顾问）**：**桥必须覆盖 `api.js` 会发的全部 `/api/**` 路径**，
> 并**包括"非 fetch"形态的调用**。两个实测教训：
>
> 1. **`keepalive.js` 用 `new EventSource('/api/v1/keepalive')`（SSE），它绕过 `api.js` 的桥适配**
>    ⇒ 在端上必然走网络栈 ⇒ 失败 ⇒ 前端 `isOffline()` 置真 ⇒ **`app.js` 把"导入/导出"按钮 `disabled`**
>    （表现为"点了没反应"）。⇒ **凡前端会用到的路径，路由表都必须给端上实现（含 SSE 路径的端上形态）**；
> 2. **禁止把 `/api/**` 一律推回网络栈**：本项目无 `INTERNET` 权限，"真实取回失败形态"没有意义，
>    只会把"功能不可用"伪装成"离线"。**只有确实未实现的路径**才允许 `501 + implemented=false`。

| 路线 | 前端改动 | 联网权限 | 备注 |
|---|---|---|---|
| **R1（建议）** | `api.js` 增加传输适配：`window.PIQNative` 存在 ⇒ 走 `@JavascriptInterface` 桥 | **不需要** | 隐私最优；无端口/无服务 |
| R2 | 零改动（`fetch('/api/v1/…')` 原样） | 需要 `INTERNET` | 与桌面架构一致；需管理回环服务 |

**桥/HTTP 的请求-响应形态必须一致**：`request(method, path, body) -> {status, json}`，
`path` 与桌面 REST 路径**逐字相同**（如 `/api/v1/cycles`）⇒ 便于两端对照与回退。

## 7 多套 UI 的契约（**定制主题包**；用户 2026-10-06 已定档 ③ 混合）

**已定**：档位 = **③ 混合**（共享内核 + 重写视图层）· 风格 = **可爱、简约** · **桌面端也支持** ·
密码门激活 · 激活后**免重复登录** · 定制内容**不开源** ⇒ **机制公开、内容私有**。

### 7.1 主题包格式（**两端同格式**）

```
themes/<id>/
├─ theme.json     { "id": "...", "name": "...", "version": 1,
│                   "minApp": "0.22.6", "entry": "index.html", "assets": ["assets/…"] }
├─ index.html     视图层入口（可整份替换；**省略则只在默认 UI 上换皮**）
├─ css/theme.css  主题变量与组件覆盖
├─ js/theme.js    可选：视图层钩子
└─ assets/…       视觉资源（图片 / 字体 / 动效）
```

**共享内核必须复用、禁止复制**：主题的 `index.html` 通过**虚拟路径**引用共享资产：

| 虚拟路径 | 指向 |
|---|---|
| `/shared/js/api.js` | 传输层（R1 桥 / HTTP 的统一封装） |
| `/shared/js/charts.js` · `/shared/js/calendar.js` | 图表与日历内核 |
| `/shared/css/base.css` | 基础版式变量 |
| `/theme/*` | 当前主题包自身 |

- **桌面**：本地服务把 `/shared` 映射到应用自带前端、`/theme` 映射到主题目录；
- **安卓**：`WebViewAssetLoader` 用同样两条映射（⇒ 两端主题包**可直接互换**）；
- **安装位置**：桌面 `%LOCALAPPDATA%\PeriodIQ\themes\<id>\`；安卓 `files/themes/<id>/`；
- **选择值**：`app_settings.ui_variant`（`default` 或主题 id）；
- **硬护栏**：主题缺失/损坏/`minApp` 不满足 ⇒ **自动回退 `default`**，且始终提供"重置为默认 UI"；
- **回归网**：**每个已安装主题都要跑同一批 BDD/哨兵**（主题 id 作参数）；**禁止**"主题没有哨兵"。

### 7.2 定制模式（**免重复登录**）契约

| 键（`app_settings`） | 含义 |
|---|---|
| `custom_mode` | `true` = 定制模式已激活（跳过登录页 + 用定制主题） |
| `ui_variant` | 当前主题 id |
| 长期凭证 | **不进 `app_settings` 明文**，进平台密钥库（Android Keystore / 桌面 DPAPI） |

启动序：`custom_mode=true` ⇒ 静默登录（凭证）⇒ 渲染 `ui_variant` 主题；
**凭证失败 ⇒ 静默降级登录页**；**主动退出账号 ⇒ 清凭证 + 清 `custom_mode` + `ui_variant=default`**
（✅ 用户 2026-10-06 已定：**退出即回默认 UI + 需要登录**）。

### 7.2.1 私有内容落点（✅ 用户 2026-10-06 已定）

| 项 | 值 |
|---|---|
| 位置 | **`001Android/Private/`**（归安卓所有；`.gitignore` 首条规则覆盖） |
| 版本控制 | **不入 git、不入 GitHub**（纯本地）⇒ 已实测 `git status` 看不到它 |
| 结构 | `Private/theme/`（主题包）· **`Private/photo/`（美术资源，用户指定名）** · `Private/notes/` |
| 无版本历史的补偿 | 定期 zip 备份到 `001\museum\private-backup-YYYYMMDD.zip`（**不引入 git**） |
| 禁忌 | 私人素材**绝不上传任何第三方**（含私有仓库）；密码/凭证**绝不写进本目录任何文件** |

⚠ **不是安全机制**：本地门，root / 应用备份即可绕过；**任何密码与凭证不得进入任何仓库（含私有仓库）**，
不得写入日志、备份或导出文件。

### 7.2.2 设置的三层归属（**`auto_login` 的裁定**；顾问 2026-10-10 已定）

| 层 | 内容 | 随 JSON 备份走？ | 落点 |
|---|---|---|---|
| **备份层（数据）** | `app_settings` 表内的字段 —— 两端**当前都是空对象**：桌面 `GET /export` 恒发 `{}`，安卓 `PiqRouter.exportData()` 同样恒发 `{}` | ✅ 走（就是 §1 里那个 `app_settings{}` 字段） | SQLite `app_settings` 表 |
| **设备级偏好** | **`auto_login` 及其凭证** | ❌ **不入备份、不参与导入导出、不进日志** | 宿主机 SharedPreferences（安卓实测文件名为 `shared_prefs/piq_settings.xml`）；令牌先经平台密钥库（Android Keystore）加密 |
| **私有内容** | 主题包 / 美术 / 笔记 | ❌ 不入 git、不入备份 | `Private/`（§7.2.1） |

**裁定：`auto_login` 是设备级偏好，只存本机，不进备份。** 两条理由：

1. §1 的备份是**数据**桥梁，不是设备偏好桥梁；
2. 自动登录凭证属于**本机安全边界**。放进备份等于把"免登录"能力随一个文件传播，
   与 §7.2.1 末句"不是安全机制……不得写入日志、备份或导出文件"的告示口径直接冲突。

⇒ **换机恢复后开关必然丢失**，用户需要在新设备上重新打开一次；这是裁定后的**预期行为**，
不是缺陷。任何"为了保住开关而把 `auto_login` 塞进备份"的实现都属于违反本条。

**命名域 ≠ 表归属（本次歧义的根源，必须写明）**：键名 `app_settings.auto_login` 里的
`app_settings.` 只是**命名域**——表示"这是一条设置，语义上落在 §7.2 那张表的命名空间里"，
**不代表它存在 `app_settings` 表中**。判据是**落点**，不是名字：安卓侧它在 SharedPreferences 的
`piq_settings.xml` 里，而 `app_settings` 表只有 `user_id` + `updated_at` 两列（R1-A 之后的空壳），
根本没有承载它的列。

- 读代码 / 读备份 / 读日志时，**不得**由键名推断存储位置；
- 反过来，**备份体里出现 `app_settings.auto_login`（或任何凭证类字段）⇒ 视为违规产物**，
  按 §5 数据与隐私纪律处理，不得因为"名字像设置"就导入或落盘。

**开关行为不因本条改变**：每次开启都要在设置页确认一次（三层意思的确认弹窗），
**不引入"记住已确认"**；关闭开关即删除已存凭证。

### 7.3 桌面端同步要求（**用户已要求"桌面最好也支持"**）

- 桌面侧需要：**主题包加载 + `ui_variant` + 密码门 + 同样的 `/shared` `/theme` 映射**；
- 现桌面用的是本地 uvicorn 服务 ⇒ `/shared` 天然是静态根，**加 `/theme/<id>` 一条路由即可**；
- **桌面侧的改动属于新轮次**（不在安卓 R1 范围内），且必须遵守桌面仓库自己的白名单与验收流程。

## 9 debug 端点（算法透视镜）的两端口径（**R7 追加**）

来源：桌面 `backend/app/routes/debug.py`（只读参考）。安卓侧实现 = `PiqDebug.kt` +
`PiqRouter` 的三个分支；`prediction_trace` 直接调**随包算法快照** `app.algo.trace.prediction_trace`（Chaquopy）。

**三条路径与桌面逐字同形**（GET、只读、不写库、不触发生成预测）：
`/api/v1/debug/model` · `/api/v1/debug/model_history` · `/api/v1/debug/prediction_trace`。
其余 `/api/v1/debug/**` 路径两端都没有消费方 ⇒ 安卓侧仍回 `501 + implemented=false`（§5 订正块）。

**两把尺子（不得混用；桌面 v0.14.0 修 BN-1 的口径登记表在两端同样成立）**：

| 口径 | 字段 | 用途 |
|---|---|---|
| 记录数口径 | `n_records_total`（旧名 `n_total_cycles`） | 三个端点的 `algorithm_stage` 徽章 + `algorithm_stage_caliber="n_records"` 自证 |
| 参与集口径 | `model_input_n`（旧名 `n_valid_cycles`）= `model_params.n_records` = `predict_core` 的 `n` | 权重分布 / 置信度 / `n_eff` / `bayes_applied` |

`model_history` 逐快照**只有**参与集口径（`algorithm_stage_by_model_input`）；其记录数口径
（`n_records_recorded` / `algorithm_stage`）**一律 `null`**，两端同此（快照与记录无一一对应关系，绝不伪造）。
"贝叶斯是否真的生效"只看 `bayes_applied`，**不得**由 `model_version` 反推。

**展示文案是响应字段**：`stage_description` / `weight_distribution.description` / `display_note` /
`caliber_note` / `prediction_trace.note` 都是**逐字**字符串（含 `%g`、`:.1f`、`:.4f` 的数字形态）⇒
安卓侧由 `PyMath.fixedFormat` / `PyMath.generalFormat` 复刻 Python 格式化，两端必须逐字相同。

**跨端逐值对照时的两类豁免字段**（R7 实测确立，写在这里免得下一轮重新吵）：

1. **时间戳**：`last_updated` 与 `history[].created_at` 记录的是"写库/导入的时刻"，
   两端必然差几秒 ⇒ 只比形态（`YYYY-MM-DD HH:MM:SS`），不比值；
2. **行身份**：`history[].prediction_id` 是 SQLite 自增行号。测量前提"桌面一用例一新库（行号从 1 起）"
   与"安卓一用例一新账号、共用同一张 `predictions` 表（行号从上一个账号之后起）"必然差一个常量 ⇒
   可比条件 = **两端条数相同 + 各自严格递增 + 逐条差值为同一常量**（这同时反证插入顺序一致）。
   业务数值不受影响，仍按 §2.0 结构比对 + 显式容差（本轮 `1e-9` 相对）逐值判。

**面板挂载位置 = 两端一致**：透视镜在**「分析」页内容之后**（`debug.js` 包装 `App.renderAnalysisPage`），
不再挂在预测页；`isDesktop()` 的 ≥1024px 宽度门控已解除（移动端同样渲染）。
安卓侧的移动端留白仍走 §4 的运行时门控 + `--piq-inset-*`（宿主注入），**前端不为安卓另写一套布局**。


## 10. R9 追加：安卓侧对备份导入的**三处受控分叉**（登记，不是豁免）

> 背景：`AGENTS.md` §6 第 1 条要求两端对同一份 JSON 备份"字段名逐字一致、能读能写"。
> 下面三条都**不改字段语义**，只改"坏输入怎么处理"与"多大的输入肯收"；
> 执行端代码注释指向本节（`StrictJson` / `ImportBodyGate`）。

| # | 分叉 | 桌面（依据） | 安卓（R9） | 理由与边界 |
|---|---|---|---|---|
| 1 | **UTF-8 BOM** | `json.loads` 对带 BOM 的串报错（R9 报告 §3 实测） | 剥掉 BOM 后照常解析 | 安卓的文件通道是页内 `FileReader.readAsText(…, 'utf-8')`，BOM 会以 U+FEFF 留在串首。**安卓宽一档**，只影响"带 BOM 的文件能不能导"，不影响任何字段取值 |
| 2 | **导入体积上限** | 无（`import_data` 不设请求体上限） | `PiqConfig.MAX_IMPORT_BYTES = 8 MiB`（JSON 文本字节），**解析之前**按长度拒 400 `IMPORT_TOO_LARGE` | 页内解析是同步的（R9 实测 10 MB 体解析 40 ms、再序列化 60 ms；R8 实测 20 MB 阻塞 694 ms），且桥路径上前端 60 s 超时不可能触发。取值依据：实测最大合法备份 6,834,114 B（`MAX_IMPORT_CYCLES=1000` × `MAX_NOTE_CHARS=2000` × `MAX_IMPORT_PREDICTIONS=2000`），余量约 23%。**边界**：只作用于 `POST /api/v1/import`，其余端点不变 |
| 3 | **坏请求体的档位** | 解不开的请求体由框架处理；空载荷/缺必要键由路由回 400 `EMPTY_IMPORT` | ① 空体 ② 非法 JSON ③ JSON 但非对象 = 422 `VALIDATION_ERROR`（与 `validationError` 单源同族）；④ 对象但缺必要键 = 400 `EMPTY_IMPORT` | 安卓把"哪里坏了"分四档，各给一句 + 一句下一步建议（R8 的 REG-05）。**未实测项**：桌面 HTTP 层对解不开请求体回 400 还是 422 本轮未起服务实测，已登记在 R9 报告 §6 待补 |

**另记一条"安卓比桌面更严一档"（不影响字段语义）**：裸 `NaN` / `Infinity` 在页内文法检查里放行
（对齐 Python `json.loads`），但装机 WebView 的 `org.json` 拒（R9 设备实测两行读数）⇒ 净效果安卓回 422。
真实备份不可能带这两个字面量：`JSON.stringify` 把 `NaN` 写成 `null`，两端导出器都不产出裸 `NaN`。

**新增的页内时机事件** `piq-insets-updated`（单源常量 `PiqInsets.EVENT_NAME`）：
生产方与消费方**都在宿主侧**（`PiqInsets.assignScript()` 派发、`AndroidGate.KEYBOARD_SCROLL` 监听），
`frontend/` 内 0 命中 ⇒ 不要求前端配合，不构成跨端契约缺口。

## 11. R9.1 追加：**未来日期上限是独立一层**，与合成夹具的日期基准绑定

> 起因（`R9审计1.md` §6.4 第 1 条）：上一轮的夹具把日期**写死成 2027**，而后端对"晚于今天"有硬上限 ⇒
> 在 2026 的时钟下那份夹具**永远导不进去**，整轮取证时间白烧。本节把这条口径钉成契约，两端共用。

**11.1 两层的分工（不许混为一谈）**

| 层 | 触发条件 | 错误身份 | 能否被 `allow_anomalies` 放行 | 两端实现位置 |
|---|---|---|---|---|
| **门禁 G1-G5**（§异常门禁） | 周期长度/相邻间隔/逾期等**统计异常**，其中 G2 也看"晚于今天" | `400 DATA_ANOMALY` + `anomalies[]` | ✅ **能**（`=true` 即放行） | 桌面 `app/services/gate.py::evaluate_gate`（`routes/settings.py` 里 `if gate_anomalies and not body.allow_anomalies`）· 安卓 `ImportGate.evaluate`（`PiqApiCore.kt`） |
| **未来日期硬上限** | 业务日期 `> date.today() + MAX_FUTURE_CYCLE_DAYS`（当前常量 **0** ⇒ 不得晚于今天） | 导入路径 `400 INVALID_IMPORT`；POST/PUT 路径 `422 VALIDATION_ERROR` | ❌ **不能**（该函数签名里根本没有 `allow_anomalies` 参数） | 常量：桌面 `app/config.py::MAX_FUTURE_CYCLE_DAYS`（安卓同源行 `app/src/main/python/app/config.py`）· 安卓 `PiqConfig.MAX_FUTURE_CYCLE_DAYS`；判定：桌面 `routes/settings.py::_reject_import_future_date`（作用于 `period_start` 与 `period_end`）· 安卓 `PiqRouter.rejectImportFuture`（同两字段）+ `rejectFutureLimit`（POST/PUT 侧） |

**11.2 一致性要求（R9.1 现查口径，不写死读数）**

1. **净效果必须一致**：`period_start` 或 `period_end` 晚于今天的记录，**两端都进不了库**，
   `allow_anomalies=true` 也拦不住；
2. **两端的先后顺序也已实测一致**（R9.1 模拟器读数，同一份 future-date 夹具两态对照）：
   `allow_anomalies` 缺省 ⇒ 先被门禁 **G2** 抓 ⇒ `400 DATA_ANOMALY` + `anomalies[]`；
   `allow_anomalies=true` ⇒ 放行门禁，随后被硬上限拒 ⇒ `400 INVALID_IMPORT`（文案含"最晚 <今天>"）。
   两态**都零写入**（行数不变）。⇒ 任何一端把这两层顺序改动，都必须同步另一端并追加本节；
   读数原文见 `docs/提示词/R9/R9.1/报告回传/R9.1报告1.md` §3.4（夹具 `c1`/`c2`）；
3. **时区口径**：两端都用**本地日历日**（`date.today()` / `LocalDate.now()`），**不得**改成 UTC
   （§2 与 `config.py` 的业务日期口径一致）；⇒ 设备时钟跨日边界会影响导入结果，这本身是判据之一；
4. **`MAX_FUTURE_CYCLE_DAYS` 改动必须由桌面先改**，安卓同轮同步（§3.9.3 同轮同值），**不得**安卓单独放宽。

**11.3 合成夹具的硬纪律（写给每一轮的取证者，两端都适用）**

- 任何"应当能成功导入"的夹具，日期一律**相对当天生成**（`base = date.today()`，倒推若干天），
  **禁止**写死年/月（R9 的 2027 夹具就是反例）；
- 需要"未来日期被拒"的反例时，用**相对量**（今天 + N 天），并显式记录生成日期与 `base_date`；
- 生成器与 `manifest.json`（每条含 `sha256` / `bytes` / `base_date` / `expected`）留在仓库外探针目录，
  复现命令写在该脚本自己的 docstring 里；**不得**把夹具塞进仓库或 `assets/`（`AGENTS.md` §5 隐私红线）；
- 若某轮必须跨天复现同一批夹具 ⇒ 用脚本的 `--base` 参数固定基准日，**不要**改设备时钟
  （R9 曾把一次性模拟器时钟调到 2027-03-15 来"迁就"写死的日期，那是把夹具的缺陷转嫁成环境副作用）。

## 13. R9.4 审计追加：**安卓侧没有迁移机制**（R-ARCH-1：事实 + 决策）

**事实**（`PiqDb`，2026-10-18 核对）：用 `SQLiteDatabase.openOrCreateDatabase(file, null)` + `DDL.forEach { execSQL }`，
**没有 `SQLiteOpenHelper` / 没有 `DATABASE_VERSION` / 没有 `onUpgrade`**。

**后果（三条，必须知道）**：

1. `CREATE TABLE IF NOT EXISTS` 对**已存在的表是 no-op** ⇒ **DDL 文本的改动只对"全新安装"生效**，
   老库的列默认值/约束永远是建立时的文本；
2. 自 R9.4 起 DDL 由 `PiqConfig` 派生 ⇒ **同一份代码在"新装用户"与"老用户"上可以有不同的列默认值**。
   当前**无行为差异**（所有写路径显式给值：`PiqCrud.resetModelParams` 的 SQL 与行缺失兜底都已接 `PiqConfig`），
   但改 `PRIOR_*` / `MIN/MAX_CYCLE_DAYS` 时必须意识到这一点 —— `SchemaDefaultTextTest` 钉的是**新装文本**，钉不住老库；
3. 真要改表结构（加列 / 改约束）⇒ **唯一可行路径 = 导出 JSON → 重装 → 导入**（备份格式即迁移载体）。

**决策（顾问 2026-10-18，默认口径）**：

- **暂不建迁移层**（理由：单机私有应用、数据可完整导出/导入、加一层 `onUpgrade` 的维护成本高于收益）；
- ⇒ **必须把"升级 = 导出 → 重装 → 导入"写进 `README.md`**，并在 `PiqDb` 的 KDoc 上写一行
  「**改 DDL 前先读契约 §13**」（否则这就是将来最可能的"屎山入口"）；
- ⇒ 若将来真需要就地升级（用户规模或数据量变化），再按"版本号 + `onUpgrade` + 逐版本迁移脚本"补，届时本节改写。

## 14. R10 审计追加：**过期会话启动期的"空壳过渡帧"是已知特征**（不是缺陷）

**现象**（R10 实测）：凭证过期后冷启，约 **1.5–3 s** 内先看到"吸底导航在、内容区空白"的过渡帧，随后才到登录页并浮现
「上次的登录已经过期，请重新输入口令。」（截图 `r10-l2e03-3-2s-shell.png` / `-4-7s-login-with-hint.png`）。

**成因**：宿主在页面加载前就播种令牌（否则前端在"无令牌"形态下不发请求，结算点永远没有触发时机，用户会被**静默**停在登录页），
而 TTL 结算必须查数据库 ⇒ 只能等首条请求到达时才发生（`MainActivity.settleStartupSession`）。

**裁定（顾问 2026-10-18）：接受为已知特征，不修。** 理由：
① 只在"过期会话启动"这一条路径上、**每 30 天一次**；② 有 Toast 解释，不是静默；
③ 另一条修法要把建表 / `Python.start` 逼到主线程（与 `PiqServices` 的纪律冲突）——
**为 2 秒观感付每次冷启的同步代价，不划算**。
⇒ 任何轮次**不得**把它记成缺陷或 `未覆盖`；若将来用户明确要求消除，再由顾问改写本节并单独立项。
